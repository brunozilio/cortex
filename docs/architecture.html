Arquitetura do Superfik

Um canvas nativo em Rust para agentes de programação. Um cliente puro, um servidor que executa tudo e um renderizador que desenha cada pixel. Esta página é o complemento visual de docs/architecture.md.

Visão geral

O cliente nunca executa nada (ADR 0010). O app desktop e a aba do navegador usam o mesmo cliente; todo comando atravessa o protocolo até um servidor, embutido no app ou mantido por um time, que cuida das execuções, do git, da memória, dos plugins, dos cofres e dos canais.

O loop do cliente: state → view → effects

O reducer é puro: Session::apply(Action) -> Vec<Effect>. Toda regra de produto é testada ali. A view nunca altera a sessão, e o shell é o único lugar onde acontece IO.

A vida de um prompt

Uma execução volta em streaming como EngineEvents marcados com um RunId, então as sessões continuam recebendo em segundo plano enquanto outra está na tela. Exatamente um evento terminal encerra a execução.

Interfaces comuns

Quase tudo que toca o mundo de fora passa por um trait pequeno. A regra fica pura de um lado, o IO do outro, e cada trait tem um substituto para os testes (Recorder, Scripted…, InMemory…). As assinaturas abaixo foram copiadas do código, sem os comentários.

Provedores de IA

O engine nativo nunca fala com um provedor diretamente: ele pede a um ApiSource a ModelApi certa para a execução. Cada provedor é um plugin (openai, openai-subscription, anthropic, claude-subscription) cujo contrato é puro em superfik_plugins::providers; o IO fica em superfik_native::model.

ModelApi

superfik-native · model/mod.rs
pub trait ModelApi: Send + Sync {
    fn turn(&self, request: &TurnRequest,
            on: &mut dyn FnMut(Delta),
            stop: &AtomicBool)
        -> Result<Reply, ModelError>;
}
pub struct TurnRequest {
    model, system, messages,
    tools: Vec<ToolSpec>, effort, max_tokens,
}
pub enum Delta { Text(String), Thinking(String) }

Um turno do modelo. O texto e o raciocínio chegam aos poucos por on; o Reply traz a mensagem completa (com as chamadas de tool), o motivo da parada e o uso.

Engines, tools e eventos

Um engine recebe uma PromptRequest e emite EngineEvents num EventSink. Hoje só o nativo está registrado; Codex, Kiro e Copilot aparecem como "Em breve" até alguém implementar o trait.

AgentEngine

superfik-engine · engine.rs
pub trait AgentEngine: Send + Sync {
    fn kind(&self) -> EngineKind;
    fn models(&self) -> Vec<ModelOption>;
    fn is_installed(&self) -> bool { true }
    fn start(&self, run: RunId,
             request: &PromptRequest,
             sink: Arc<dyn EventSink>)
        -> Result<Box<dyn RunHandle>, EngineError>;
}
pub trait EventSink: Send + Sync {
    fn emit(&self, run: RunId, event: EngineEvent);
}
pub trait RunHandle: Send {
    fn cancel(&mut self);
    fn answer(&mut self, ask: &AskId, d: &Decision) {}
    fn set_mode(&mut self, mode: PermissionMode) {}
}

Exatamente um evento terminal (Completed, Failed, Cancelled) encerra uma execução.

Tool

superfik-native · tools/mod.rs
pub trait Tool: Send + Sync {
    fn spec(&self) -> ToolSpec;
    fn access(&self) -> Access;
    fn summary(&self, input: &Value) -> String;
    fn run(&self, input: &Value,
           workspace: &Workspace) -> Outcome;
}
pub enum Access { Reads, Edits, Executes }
pub struct Outcome { content, is_error, images }

Access decide as permissões: o modo Plan só deixa Reads, e no modo Bypass a checagem de segurança avalia tudo que é Edits ou Executes antes de rodar.

Plugins

Um plugin é uma pasta com superfik-plugin.json, mais skills/ e agents/ opcionais. O catálogo curado vem embutido de crates/superfik-plugins/catalog/<id>/; "Adicionar de pasta…" instala qualquer outro. A mesma forma serve para ferramentas MCP, provedores de IA, cofres e canais: o que muda é o campo que o manifesto preenche.

Um manifesto real

catalog/linear/superfik-plugin.json
{
  "id": "linear",
  "name": "Linear",
  "accounts": "many",
  "auth": { "kind": "oauth" },
  "mcp": [{
    "transport": "http",
    "name": "linear",
    "url": "https://mcp.linear.app/mcp",
    "headers": {

    }
  }],

Cada conta ganha um nome de servidor próprio (linear-acme), então duas contas do mesmo plugin nunca se misturam.

Como estender

  1. Um plugin de ferramentasUma pasta em crates/superfik-plugins/catalog/<id>/ com o manifesto (auth e servidores MCP) e, se quiser, skills/ e agents/. Nenhum código Rust.
  2. Um provedor de IAO contrato puro em superfik_plugins::providers (credencial, catálogo, formato da requisição), uma variante em ModelProvider, um ModelApi em superfik_native::model testado contra streams gravados e a escolha em NativeApis.
  3. Um engineImplemente AgentEngine com o IO atrás de costuras e registre em LocalServices::detect. Ele substitui sozinho a linha "Em breve"; UI, protocolo e reducer não mudam.
  4. Um cofreUma variante em VaultKind, um VaultProvider registrado em VaultProviders::system e um manifesto com "vault".
  5. Um canalUm ChannelKind com seus limites, um Opener/Channel (sobre Http se for API oficial) e um manifesto com "channel".
  6. Um dispositivoUma parte pura, o dispositivo atrás de um trait, Recorder para os testes e o shell executando o Effect.

Crates, de cima para baixo

As dependências apontam para um só lado: para baixo. Regras de negócio nunca dependem de IO, e componentes de UI nunca dependem de regras de negócio.

Local e time

Sozinho, o app conversa com o servidor embutido nele, como dono local. Conectado ao servidor de um time, o mesmo cliente fala com ele como membro; o servidor tem os próprios usuários (ADR 0017) e executa tudo por eles.

As regras que mantêm esse formato

Reducer puro

Regras de domínio ficam em superfik-core ou state/. IO só acontece por Effects.

Componentes sem estado

Recebem props, pintam e devolvem a geometria de clique. Usado duas vezes vira componente.

Só tokens

Toda cor, tamanho, fonte e duração vem de superfik-ui/theme.

IO atrás de traits

Todo dispositivo e serviço tem uma costura e um substituto, então todo comportamento ganha teste.

Um Principal em tudo

Comandos viajam num Envelope e passam por um Authorizer; a costura do backend fica intacta.

Fatos, não frases

O core guarda fatos; o superfik-i18n transforma em texto na hora de pintar.
